## 1. 背景与目标

千问会议记录已经做到了「浏览器里一键实时转写 + AI 纪要」，但存在三个问题：**只录音不录视频**、**数据必须存在厂商云端**、**模型不可选**。

**产品目标**：做一个开源的会议记录 Chrome 插件——装上即用、无需部署，一键录制音频或视频，用用户自己的 API 完成转写和纪要，得到 **视频 + 逐字稿 + AI 纪要** 联动的会议记录，所有内容只存在用户自己的机器上。

**MVP 成功指标**

- 从安装插件到完成第一次录制 ≤ 3 分钟（含选择数据文件夹、配置 API）
- 插件从点击到开始录制 ≤ 2 步、≤ 3 秒
- 60 分钟会议录制成功率 ≥ 98%（无中断、音画同步误差 ≤ 200ms）
- 会后纪要生成 ≤ 60 秒（取决于所配模型）
- 开源指标：发布 3 个月内 GitHub Star ≥ 1k、Release 下载 ≥ 3k

## 3. 竞品页面拆解（基于千问会议记录截图）

### 3.1 插件弹窗页

- 顶部：Logo、「访问网页版」、关闭
- Tab：阅读助手 / 实时记录（**我们只做会议记录，不做阅读助手**）
- 设置项：同时录制本地麦克风、音视频语言、翻译语言、更多设置
- 主按钮「开启实时记录」，底部「查看历史记录」

### 3.2 录制中侧边栏

- 状态卡：波形动画、「录音中」+ 计时、结束 / 暂停 / 翻译 / 折叠
- 下方实时字幕流，按时间戳分段

### 3.3 录制结果页（Web）

- 顶栏：标题、自动保存时间、收藏、导出
- 左栏「语音转文字」：发言人 + 时间戳分段，发言人可改名；搜索、筛选、编辑
- 底部播放条：±15s、播放、波形进度、倍速
- 右栏：导读（关键词、全文概要、章节速览 / 发言总结 / 要点回顾 / 待办事项）/ 脑图 / 笔记

### 3.4 我们的差异点

1. **视频录制**：标签页 / 窗口 / 全屏 + 可选摄像头画中画
2. **结果页以视频为主**：视频播放器与逐字稿、章节双向联动
3. **画面关键帧**：自动截取屏幕共享翻页画面，插入章节与纪要
4. **开源 + 免部署 + 全本地存储**：只装一个插件，数据是本地文件夹里的普通文件
5. **模型自选**：兼容 OpenAI 协议的任意大模型；转写支持多家云 API（录音文件识别）

## 4. 系统形态

```
┌──────────────────────── Chrome 插件（会录）────────────────────────┐
│ 弹窗：录制设置          侧边栏：计时 / 暂停 / 结束 / 打点 / 笔记   │
│ Offscreen Document：采集 + MediaRecorder 录制 + 分片写盘           │
│ 插件内网页：历史记录 / 结果页 / 设置（普通标签页中打开）           │
│ 后台任务：转写、纪要生成、关键帧提取                               │
└───────────┬───────────────────────────────────────┬────────────────┘
            │ File System Access API                │ HTTPS（用户自己的 Key）
┌───────────▼──────────────┐          ┌─────────────▼──────────────┐
│ 用户选择的本地文件夹     │          │ 转写：云端录音文件识别 API │
│ ~/Documents/HuiLu/...    │          │ 大模型：OpenAI 兼容接口    │
└──────────────────────────┘          └────────────────────────────┘
```

- **没有服务端**：插件就是完整产品；不依赖任何 huilu 官方服务器
- 唯一的外部网络请求是发往用户所配置的转写 / 大模型服务商；大模型可接本地 Ollama
- **数据文件夹结构**（每场会议一个子文件夹，全部是可直接打开的普通文件）：

```
HuiLu/
└── 2026-09-24_1430_需求评审/
    ├── meeting.json      # 元数据：标题、时间、时长、发言人、打点
    ├── video.mp4         # 视频（仅音频模式时无此文件）
    ├── audio.webm        # 低码率纯音频，用于转写
    ├── transcript.json   # 逐字稿（发言人 + 时间戳）
    ├── summary.md        # AI 纪要（可直接阅读）
    ├── notes.md          # 用户笔记
    └── frames/           # 画面关键帧
```

- 卸载插件不影响数据；备份 / 迁移 = 复制文件夹；更换电脑后在设置中重新选择该文件夹即可恢复全部记录
- 插件内部用 IndexedDB 缓存列表与搜索索引，可随时从文件夹重建

**远期可选**：核心逻辑（数据格式、转写/大模型接入层）放在独立的公共包中；如有局域网 / NAS 访问需求，再提供读取同一数据格式的 Docker 服务，无需返工。

## 6. 核心流程

**首次使用**：下载 Release 压缩包并解压 → 开发者模式加载插件 → 自动打开引导页 → 选择数据文件夹并授权（建议勾选「始终允许」）→ 配置转写 API、大模型 API（各自测试连接）→ 完成

**录制**：点击插件 → 选择「音频 + 视频」及来源 → 开始记录 → 浏览器授权共享 → 侧边栏显示计时与控制 → 结束并确认 → 合成文件、整体转写、生成纪要（进度可见，60 分钟会议约 1–3 分钟）→ 自动打开结果页

**回看**：历史记录 → 打开记录 → 读导读 / 章节 → 点击章节跳到视频对应位置 → 编辑笔记 → 导出

## 7. 非功能需求

- **安装**：插件包 ≤ 5MB（不含可选的 ffmpeg.wasm，按需下载）；macOS、Windows、Linux 的 Chrome / Edge 均可用
- **性能**：插件录制时 CPU 占用 ≤ 20%（720p/15fps 参考）；分片每 5 秒落盘，崩溃最多丢失 5 秒
- **容量**：720p 约 300–500MB/小时；磁盘空间不足时提前警告
- **兼容**：Chrome / Edge 最新两个大版本
- **隐私**：不收集任何遥测；除用户配置的 ASR / LLM 服务商外不发任何外部请求；录制开始时页面内有明显提示；支持一键删除全部数据
- **可用性**：ASR / LLM 调用失败不影响录制，任务自动重试，并可手动「补转写」
- **开源**：代码托管 GitHub，提供 README、部署文档、贡献指南；每个版本在 GitHub Release 提供插件压缩包；暂不上架 Chrome 应用商店

## 8. 技术方案要点

- **插件框架**：Chrome MV3 + WXT + React + TypeScript + Tailwind；Side Panel API 做侧边栏；界面支持简体中文与英文（完整技术架构见 [ARCHITECTURE.md](ARCHITECTURE.md)）
- **采集与录制**：`chrome.tabCapture` 采集标签页音视频，`getDisplayMedia` 采集窗口/屏幕，`getUserMedia` 采集麦克风/摄像头；Offscreen Document 中用 Web Audio 混音、MediaRecorder 录制（Chrome 支持直接输出 MP4/H.264）；同时另录一路低码率纯音频（约 15–30MB/小时）专用于转写
- **存储**：录制中分片先写入 OPFS（无需授权，最稳定），结束后整理写入用户数据文件夹；元数据与索引缓存在 IndexedDB（Dexie）
- **插件 ID**：manifest 固定 `key`，本地加载时 ID 稳定
- **转写**：统一的 ASR Provider 接口。MVP 接入：阿里云百炼 Paraformer 录音文件识别（通过百炼临时文件上传获取 URL，含发言人区分）、OpenAI 兼容转写接口（超出单文件大小限制时按静音点切片后合并）
- **纪要**：统一的 LLM Provider 接口（OpenAI 兼容协议），按模板生成结构化 JSON（关键词、概要、章节、发言总结、要点、待办），同时写出 `summary.md`
- **视频处理**：关键帧用 Canvas 对视频逐帧差异检测截图；片段剪辑等（P2）按需加载 ffmpeg.wasm
- **仓库**：pnpm + Turborepo monorepo——`apps/extension`、`packages/core`（数据格式、扩展点接口）、`packages/i18n`、`packages/ui`，以及后续的 recorder / storage / providers / pipeline / exporters

## 8.1 技术验证项（开发前先做）

1. File System Access 授权持久性：Chrome 122+「始终允许」的实际表现；旧版本的重新授权体验
2. 长时间录制：2 小时 1080p 录制的内存占用与分片落盘稳定性
3. 百炼 Paraformer 录音文件识别 + 临时文件上传在插件环境中的调用链路
4. MediaRecorder 直接输出 MP4 的兼容性与音画同步
