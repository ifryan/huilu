# U-59 历史记录编辑与可恢复归档

## 使用与数据规则

历史记录每行增加「编辑标题」「归档」，归档前确认；顶部「会议记录 / 已归档」切换列表，已归档记录可确认恢复，也可编辑标题、打开详情。中英文、搜索、刷新重建均支持。对话框限制焦点、支持 Tab / Shift+Tab / Escape，取消返回原按钮，归档或恢复移除当前行后返回当前列表入口。

- 标题写入权威来源的 `meeting.json`：文件夹记录写原目录，本机记录写 OPFS。物理目录、录制清单和媒体文件不重命名。本机列表改为优先读会议标题，清单标题只作无元数据时的兜底。
- 新增可选 `archived` 字段，旧会议默认未归档；沿用现有 schemaVersion 1 的可选用户编辑字段约定。默认列表隐藏已归档记录，直接打开详情仍可访问。旧版本插件可能忽略该字段并显示这些会议。
- 仅改会议元数据，保留未知字段、媒体、说话人、标记、逐字稿、纪要、任务错误和断点。归档不删除 OPFS 或用户文件，不新增永久删除入口。
- 所有编辑复用跨页面 Web Lock，字段 `previous` 比较防止陈旧覆盖，写入后校验。处理队列预约也取得同一把锁；归档的本机或已提交文件夹会议不重新入队。恢复后原失败任务仍可重试。
- 正在录制、未恢复的中断录制、queued / running / waitingFolder 任务暂停编辑和归档；损坏、重复 ID、无授权记录禁用操作。保存时重新验证来源、文件夹身份、权限和任务状态，避免对话框打开后发生变化。
- 空白标题不保存，最长 200 字符。取消不写盘。失败保留对话框并提示刷新核对、检查授权与空间，不以乐观缓存冒充保存成功。任意存储系统故障后的最终落盘状态仍应刷新核对。

## 验证内容

`pnpm check`：格式、lint、类型及 501 项测试；`pnpm build`：扩展构建。新增测试覆盖持久化归档/恢复、独立媒体与文本不变、未知元数据保留、竞争写拒绝、处理期间拒绝、空白标题、写失败、权限撤回、切换根目录、已归档任务不入队，以及最终目录优先于旧 OPFS。

浏览器驱动 `scripts/verify-u59-browser.mjs` 加载实际构建，使用隔离 Chrome 156 / X11 profile；仅生成 WAV 音频、蓝色视频和测试会议。普通成功路径通过原生文件夹选择器与 Chrome 编辑授权确认，读写临时授权目录，并独立读写实际 OPFS / IndexedDB。带视频会议的详情视频已加载帧数据（readyState ≥ 2），时长至少 1 秒；不以仅存在文件作为成功依据。正常流程不替换文件系统原型。

文件夹与本机来源分别执行：空标题、Escape 取消、标题保存、页面重新加载、搜索、详情、归档取消、归档隐藏、刷新后仍隐藏、归档列表查找与恢复。对文件夹和 OPFS 的音视频、录制清单、逐字稿、纪要做前后 SHA-256 比较；任务记录和断点逐项相等，目录名称不变。失败本机记录恢复后仍可重试。

单独标记的注入验证：

- 两个真实插件页面同时编辑同字段，第二个陈旧保存被拒绝；实际 Web Lock 与源文件比较生效。
- `createWritable` 注入 QuotaExceededError，提示失败且源元数据未变。
- `queryPermission` 注入 denied，保存被拒绝并显示授权/空间核对提示；这不冒充操作系统撤权。
- 对话框打开后在隔离任务库注入 running，提交被拒绝；任务恢复原值。
- 390px 中文页面、对话框无横向溢出；Tab / Shift+Tab 保持在对话框，Escape 取消并恢复按钮焦点，成功提示随语言切换。

## 累积回归与边界

复用本批既有驱动，在 U-59 累积版本验证：

- `verify-u64-browser.mjs`：缺音轨与混音边界、数字静音和坏音频检查；真实离屏队列遇静音标为 silentAudio，服务商调用为 0。
- `verify-u93-browser.mjs` 原生组：取消/关闭选源、互斥、标签页/窗口/全屏选源、暂停/继续、控制关闭/恢复、导航后恢复、结束保存及采集页/浮层清理。原生标签页合成 440Hz 声源录到 53,557 字节、幅值约 0.201；这不是实体系统声音测试。
- 独立注入组：来源音频未授权/缺轨时拒绝且不提前打开 mic；440/880Hz 混音、仅 mic、无声视频无 audio 字段、未知来源拒绝、强关采集页后的 OPFS 恢复。注入不代表实体设备通过。
- 125% 小屏原生组继续覆盖 U-92/U-95 选源与 U-93 生命周期。U-94 网页面板单层样式、关闭后页面宿主归零、原生条仍独立存在；主动 Hide 后录制继续。

记录的各组构建来源见审查包清单。最终几项后续修正仅涉及历史页的权限错误分类、语言提示、键盘焦点，不修改采集、混音或录制生命周期模块。

U-94 原图的 Chrome 原生共享条外框仍是其独立 blocked 项，不能把网页面板样式或本项交付说成原图修复，也不能据此宣称本批七项已交审。显式快捷 tabCapture → offscreen 路径的既有 NotFoundError 保留。未测实体麦克风、多屏、Windows/macOS、真实 ASR、原 ADR 的跨平台 AAC/CPU 等；本次临时目录成功不代表所有系统上的文件夹授权均通过。

## 复现

```bash
pnpm install --frozen-lockfile
pnpm check
pnpm build
PLAYWRIGHT_MODULE=/path/to/playwright-core/index.mjs \
CHROMIUM_PATH=/path/to/chrome \
XVFB_PATH=/path/to/Xvfb \
node scripts/verify-u59-browser.mjs
```

需有 xfwm4、xdotool、xwininfo、ffmpeg（含 libx264/AAC）、tesseract。脚本为隔离 X11 桌面选择临时目录，并在 finally 中关闭自身创建的浏览器与子进程。不要复用私人浏览器 profile 或真实会议目录。

```bash
# 原生桌面 / 125% 小屏；其余路径参数同上
AUDIT_SHARING_UI=1 SCALE=1.25 SCREEN_SIZE=1200x900x24 \
node scripts/verify-u93-browser.mjs
# 明确注入的边界测试
AUDIT_SHARING_UI=1 INJECT_CAPTURE=1 node scripts/verify-u93-browser.mjs
node scripts/verify-u64-browser.mjs
```

手工验收：解压可加载插件包，Chrome 扩展页开启开发者模式，加载包含 manifest.json 的目录；用新建的临时数据文件夹及隔离录制测试。历史页编辑标题，刷新并打开详情核对；归档确认后切到「已归档」，搜索并恢复。对失败记录重复同流程，确认恢复后仍能看到原错误和重试。录制/处理期间操作应禁用；关闭操作对话框后可继续用键盘浏览列表。最终由 RH / Chief 验收，不直接 done。
