# U-41～U-44 录制控制修复与非浏览器验证

基线：`main@c1a2d9e025b2856643acee21ecf625089746ac1b`。RH 明确要求本批不进行任何浏览器测试；所有新增回归在 Node 中运行，使用 DOM、Chrome API、Web Audio 和 MediaStream 替身。

## 行为变化

- **U-41**：封闭 Shadow DOM 中的 manual popover 进入浏览器顶层，避免受宿主网页的普通层叠上下文、transform、overflow 影响。背景不拦截点击；对话框 / 全屏切换、宿主节点移除时重新定位。保留拖动、收起、关闭后从插件图标重开；拖动按面板实际尺寸限制边界，处理 pointercancel。
- **U-42**：复用麦克风预览的 RMS / dBFS 算法，在录制混音总线上采样；悬浮面板和弹窗均显示真实电平。录制时每 200ms 查询，暂停 / 收尾 / 结束为零，不额外打开麦克风，也不使用装饰性波形。低于 -60dBFS 显示零电平。
- **U-43**：新增独立于麦克风的来源 / 系统音频开关，记住选择；旧偏好缺少字段时默认开启，保持原行为。桌面选源仅在开启时请求 audio，并检查原生授权与实际返回的音轨；即使关闭时意外收到音轨，也会停止且不接入混音。来源音频缺失时单独提示，即使麦克风仍可录制。无输入的视频不生成转写音轨，仅音频录制无输入时拒绝开始。
- **U-44**：同步且幂等地卸载 React，取消未完成的挂载；扩展上下文失效或页面离开时清理轮询、语言监听和 DOM 监听。结果通知与清理隔离，短暂断连最多重试两次，后台持久去重；打开结果页失败时释放通知 claim，保留错误诊断。

来源音频的可用性取决于浏览器、系统、所选来源及用户原生授权，不承诺所有窗口 / 屏幕都能采集系统声音。参见 [Chrome desktopCapture 文档](https://developer.chrome.com/docs/extensions/reference/api/desktopCapture)；顶层浮层机制参见 [Popover API 文档](https://developer.mozilla.org/en-US/docs/Web/API/Popover_API)。

## 三类错误的证据与边界

| 截图错误                        | 源码证据 / mock 触发路径                                                                                                                                         | 修复与验证                                                                                                            |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `Extension context invalidated` | 旧面板没有主动检查 WXT 的 `ctx.isValid`；异步挂载和部分按钮消息缺少 rejection 处理。模拟 storage / message 抛出该错误。                                          | 限定识别这一预期错误后清理上下文；其他异常仍记录。挂载取消、失效清理测试通过。                                        |
| `removeChild` 非子节点          | WXT 0.21.4 的 `createShadowRootUi.remove()` 在调用 `onRemove` 后立即清空容器；旧 `onRemove` 通过 Promise `.then` 延迟 React 卸载，顺序确定存在竞争。             | `mountInto` 立即返回同步清理句柄；React 卸载先于 WXT 清空，重复卸载无作用，异步初始化完成后不会重新挂载已移除的面板。 |
| 结果通知 `message port closed`  | 旧 `processingIdle` / `recordingFinished` 在响应处理内关闭离屏文档；结果页打开操作没有单独计入使用中的离屏任务。模拟空闲通知与延迟的结果投递并发，以及响应丢失。 | 下一事件循环再清理；投递期间持有使用计数，并在异步空闲检查之后复查；断连有限重试，成功持久去重，打开失败释放 claim。  |

原截图只有构建后的 overlay 行号，另外两类堆栈未展开，且未提供用户实际加载的精确构建 SHA。因此，上表中的源码缺陷与 mock 验证是可检查证据；**不能断言截图的每一条历史错误都已被实机复现或精确归因**。

## 验证结果

- `pnpm check`：通过，包含 Prettier、ESLint、TypeScript、**446 项单元测试**；本批新增 26 项回归。
- `pnpm build`：通过，Chrome MV3 生产构建成功。
- `git diff --check`：通过。
- 新增回归覆盖来源开关的三类采集源、旧设置默认值、浏览器未提供音轨、关闭音轨不混音、无声视频不可转写、真实采样算法、暂停 / 恢复 / 停止电平、启动失败释放设备、面板卸载竞争、顶层宿主切换与监听清理、结果通知并发与有限重试。
- OPFS 分片写后校验、开始互斥、实际 MIME 探测、会议存储 schema、服务商设置和密钥存储路径保持原有实现，并通过现有回归。
